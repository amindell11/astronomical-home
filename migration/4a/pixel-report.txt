3. Why the golden image wobbles for Valis
   - Main's own prefab, rendered in a branch-tree session, misses main's golden image by the same
     5-8 pixels (session O vs main-run2), and lands within 1-6 px of branch-run2.
   - Same prefab, same session, with the hull's eight materials re-instanced: forward creation order
     changes 73 pixels (max 326), reverse order 5 pixels (max 118). Valis's coplanar paint submeshes
     tie in depth (DrawnSurface: ZTest LEqual, no offset; the contour is stencil-masked by them), so
     which wins at a tie follows URP's opaque draw order, and that order keys on material identity,
     which is assigned per session by load order.
   - Crimson, Nightshade and Vanguard were stable across these runs.

Verdict: the migrated Valis renders pixel-identical to main's Valis at every harness pose when both
render in one session. The golden image as written (baseline from one session, render in another)
cannot reach zero for Valis even for main's own prefab; that is a harness property, not the migration.
